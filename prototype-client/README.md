# prototype-client

Private workspace ESM API client generated by Orval from `prototype-api/openapi.json`. No Axios or other runtime dependency: it uses native Fetch (browsers and Node.js 24). The `prototype` workspace already depends on this package; nothing needs to be published or manually copied into `node_modules`.

## Generate

From the repository root:

```bash
pnpm install
pnpm client:generate
```

This builds the Nest API with the Swagger compiler plugin, exports `prototype-api/openapi.json`, generates `prototype-client/src/generated/api.ts`, and compiles JavaScript and declarations into `prototype-client/dist/`.

Individual steps:

```bash
pnpm openapi:generate                       # Export the contract only
pnpm --filter prototype-client generate      # Generate + build from the existing contract
pnpm --filter prototype-client build         # Compile existing client source only
pnpm --filter prototype-client test
```

Commit the contract and generated TypeScript with API changes. `dist/` is ignored. The prototype's `dev` and `build` scripts build this package automatically from the committed source; regeneration is only needed when the API contract changes.

## Use in the prototype

```ts
import { getHello } from 'prototype-client';

const response = await getHello();
if (response.status !== 200) throw new Error(`API returned ${response.status}`);
console.log(response.data); // string: "Hello World!"
```

The default base URL is `/api`. Start both apps (`pnpm --filter prototype-api dev` and `pnpm --filter prototype dev` in separate terminals); Vite proxies `/api/*` to `http://localhost:3000/*`, avoiding development CORS issues. If you change the API port, update the proxy target in `prototype/vite.config.ts`.

## Runtime base URL / Node.js

```ts
import { getHello, setApiBaseUrl } from 'prototype-client';

setApiBaseUrl('http://localhost:3000');
const { data, status } = await getHello({
  headers: { Accept: 'text/plain' },
  signal: AbortSignal.timeout(5000),
});
```

Set the base URL once at application startup. In Node it must be absolute. In a Vite app you can use `setApiBaseUrl(import.meta.env.VITE_API_BASE_URL ?? '/api')`. This setting is shared module state, not per-request configuration; do not change it per user/request in SSR.

Vite's proxy applies only in development. In production, either configure your web server to reverse-proxy `/api` to Nest, or set an absolute backend URL and configure appropriate backend CORS permissions. This change does not enable unrestricted CORS.

Generated Fetch functions return `{ data, status, headers }`. Native Fetch does not reject HTTP error statuses; check `status`. Network failures and cancellation do reject. Response types reflect documented statuses only; undocumented server errors are still possible. No runtime response validation is performed.

Operation names come from OpenAPI `operationId`; use explicit unique IDs in backend controllers to avoid accidental client API renames. Do not hand-edit `src/generated/api.ts`.
