# Draft Docs

This directory preserves insights, decisions, and reasoning from project discussions so they do not become undocumented assumptions or get lost.

Drafts may eventually become part of IFS Standards, the repository README, or other documentation. They are not canonical standards and do not imply that a proposal has been implemented.

## Workflow

1. Identify a discussion outcome worth documenting.
2. Ask the user for approval to create or update a topic draft.
3. After approval, save it in a descriptively named Markdown file, with one topic per file. Update an existing topic draft instead of creating a duplicate.
4. Record the context, conclusion, reasoning, useful examples, and unresolved questions. Clearly distinguish agreed conclusions from proposals.
5. Note the intended documentation destination when known; otherwise mark it as undecided.

Creating this directory does not authorize automatically saving every discussion. Moving a draft into canonical documentation is a separate step.
